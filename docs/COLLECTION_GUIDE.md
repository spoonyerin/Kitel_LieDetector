# TruthPulse 데이터 수집 가이드 (진행자용)

- 작성일: 2026-11-04
- 대상: 개발 경험이 없는 진행자. 명령은 그대로 복사해서 붙여 넣으면 된다.
- 근거: `collector/record_session.py`의 상단 설명과 코드. 코드에서 확인할 수 없는 내용은 **[확인 필요]**로 표시했다. 추측으로 채우지 않았다.

이 수집은 **게임(오락)과 연구용**이며 의료·법적 판단 목적이 아니다. 참가자에게도 그렇게 안내한다.

## 1. 준비물과 사전 확인

| 준비물 | 비고 |
|---|---|
| 노트북 (Windows) | 저장소 폴더와 `.venv`가 준비된 PC. 처음이면 `docs/development.md` 3절의 "처음 한 번" |
| TruthPulse 기기 (ESP32 + 센서) | 펌웨어 KITEL_MAIN_V5 |
| USB 케이블 | 기기와 PC 연결 방식(USB인지 블루투스인지)은 **[확인 필요]** |
| 동의서 (6절 양식) | 참가자 1명당 1장 |
| 질문 기록지 | 15문항 목록에 참가자가 "거짓으로 답할 질문"을 표시하는 종이. 정해진 양식은 코드에 없다 **[확인 필요: 기록지 양식]**. `collector/question_bank.csv`의 번호(no)와 질문을 그대로 옮겨 쓰면 된다 |

### 1.1 꼭 지킬 주의

1. **수집기와 서버는 같은 COM 포트를 동시에 열 수 없다.** 수집 중에는 TruthPulse 서버(`uvicorn server.app:app`, `scripts\start_demo.ps1`)와 Arduino IDE 시리얼 모니터를 모두 닫는다. 이미 열려 있으면 수집기가 "포트 … 열기 실패"를 출력하고 끝난다.
2. 수집기는 포트를 열면서 **ESP32를 일부러 재부팅**한다(DTR 신호). 기기가 다시 켜지는 것은 정상이다.
3. 기기의 COM 포트 번호는 PC마다 다르다. 아래 명령으로 확인한다 (포트를 열지 않음).
   ```
   .venv\Scripts\python.exe -m server.cli ports
   ```

### 1.2 기록이 저장되는 위치 (중요)

코드 확인 결과(`record_session.py` 1203·1205행): 저장 폴더 `--out`의 기본값은 `experiments`, 질문 은행 `--bank`의 기본값은 `question_bank.csv`이고, **둘 다 명령을 실행한 폴더 기준**이다.

| 실행한 폴더 | 옵션 없이 실행하면 |
|---|---|
| 저장소 루트 (`Kitel_LieDetector`) | 기록이 `Kitel_LieDetector\experiments\`에 생기고, 질문 은행을 찾지 못해 **수동 모드**로 실행된다 (라벨 자동 기록 안 됨) |
| `collector` 폴더 | 기록이 `collector\experiments\`에 생긴다. `collector/` 안에 데이터가 섞이므로 쓰지 않는다 |

학습·리포트 도구는 `data\real\experiments`만 읽는다. 그래서 **항상 저장소 루트에서 `--out`과 `--bank`를 직접 지정**한다 (2절 명령). `data/`는 깃에 올라가지 않는다(`.gitignore`).

## 2. 수집기 실행

PowerShell을 열고 저장소 루트로 이동한 뒤 실행한다. `COM6`과 `P01`은 바꾼다.

```
cd C:\_Coding\Kitel_LieDetector
.venv\Scripts\python.exe collector\record_session.py --port COM6 --participant P01 --out data\real\experiments --bank collector\question_bank.csv
```

| 옵션 | 뜻 (코드 기준) |
|---|---|
| `--port` | 기기 COM 포트 (기본 COM6) |
| `--participant` | 첫 세션 참가자 별칭 (기본 P01). 세션이 끝나면 P02, P03…으로 자동 증가 |
| `--out` | 기록 폴더. 실행할 때마다 그 안에 `run_<날짜>_<시각>` 폴더가 새로 생긴다 |
| `--bank` | 질문 은행 15문항 |
| `--baud` | 통신 속도 (기본 115200, 바꾸지 않는다) |
| `--no-clear` | `new` 입력 뒤 화면을 지우지 않음 (쓰지 않는다. 지워야 거짓 표시가 화면에 남지 않는다) |

정상이면 다음이 보인다.

```
질문 은행 15문항 불러옴: collector\question_bank.csv  (실험 모드)
COM6 연결됨. ESP32 재부팅 신호 전송 완료 — BOOT 메시지 수신 대기 중...
저장 폴더: C:\_Coding\Kitel_LieDetector\data\real\experiments\run_...
[OK] ESP32 확인 (KITEL_MAIN_V5). (명령 도움말: h)
>>> 참가자 기록지를 받은 뒤 입력:  new P01 2 5 9 11 14
```

- "수동 모드로 실행합니다"가 나오면 `--bank` 경로가 틀린 것이다. `quit`으로 끝내고 다시 실행한다.
- BOOT 메시지가 안 나오면 ESP32의 리셋 버튼을 직접 누른다 (수집기 안내 문구).
- 끝낼 때: `quit` 입력 후 Enter (또는 Ctrl+C). 둘 다 저장하고 끝낸다.

수집기 입력 명령 (입력 후 Enter, 수집기 `h` 도움말과 같음):

| 명령 | 뜻 |
|---|---|
| `new P01 2 5 9 11 14` | 참가자 별칭 + 기록지에서 "거짓"으로 표시한 질문 번호 |
| `s` | 현재 상태 |
| `fix 3 l` | 질문 3번(시도 번호)의 최종 라벨을 거짓으로 고침 (`t` 진실, `l` 거짓, `x` 분석 제외) |
| `p P02` | 다음 세션 참가자 별칭만 바꿈 |
| `h` | 도움말 |
| `quit` | 저장하고 종료 |

## 3. 참가자 모집과 동의

1. 모집할 때 목적(오락용 게임 개발과 판정 방법 연구), 걸리는 시간 **[확인 필요: 1인당 소요 시간]**, 수집 항목을 미리 알린다.
2. 실험 전에 6절 동의서를 읽고 서명을 받는다. 서명한 동의서는 데이터와 따로 보관한다 (동의서에는 실명이 있으므로 PC의 데이터 폴더에 넣지 않는다).
3. 참가자마다 **별칭**을 정한다: `P01`, `P02`… 형식을 권장한다. 별칭은 폴더·파일 이름(`participant_P01_trial01_samples.csv`, 세션 폴더 `20261104_S01_P01`)에 그대로 들어간다.
   - 실명, 이니셜, 학번, 연락처를 별칭으로 쓰지 않는다.
   - 공백과 특수문자(`\ / : * ? " < > |`)는 쓰지 않는다 (파일 이름이 되므로).
   - 별칭과 실명의 대응표는 만들지 않는 것이 원칙이다. 철회 요청 처리에 꼭 필요하면 데이터와 분리된 종이에만 둔다 **[확인 필요: 대응표 보관 방침]**.
4. 같은 사람이 다시 참여하면 처음과 같은 별칭을 쓴다 (참가자 분리 검증이 별칭 기준이다).

## 4. 세션 진행 순서

### 4.1 거짓으로 답할 질문 고르기 (참가자)

1. 참가자에게 질문 기록지(15문항)를 주고, **거짓으로 답할 질문을 표시**하게 한다. 수집기 규칙: 최소 3개, 권장 5개, 표시하지 않은 문항이 최소 4개 남아야 한다.
2. 수집기는 표시한 문항에서 거짓 질문을, 표시하지 않은 문항에서 진실 질문을 고른다. 그러므로 참가자에게는 이렇게 안내한다:
   **"표시한 질문이 나오면 거짓으로, 표시하지 않은 질문이 나오면 사실대로 답하세요."**
3. 본 질문 5개 중 거짓 질문 수는 `new`를 입력할 때마다 2개, 3개, 2개, 3개… 순서로 번갈아 정해진다 (코드 기준). 진행자와 참가자 모두 어느 질문이 몇 번째로 나올지 모른다.

### 4.2 계획 입력 (진행자)

1. 기록지를 받아 수집기에 입력한다: `new P01 2 5 9 11 14` (P01 = 별칭, 뒤 숫자 = 표시한 번호).
2. 입력하면 화면이 지워지고 "질문 계획 준비 완료"가 보인다. **거짓 표시 정보는 화면에서 지워졌으므로 이제 진행자가 화면을 봐도 된다.** 기록지는 진행자가 보지 않게 뒤집어 둔다 **[확인 필요: 진행자가 표시를 봐도 되는지 실험 설계 방침]**.
3. `new`는 기준 측정(Baseline) 전이나 기준 측정 중, 첫 질문이 시작되기 전에 입력한다. 늦으면 "질문 계획이 없습니다" 경고가 나온다.

### 4.3 기기 진행 (버튼)

| 단계 | 진행자가 할 일 |
|---|---|
| 손 올리기 | 참가자가 센서에 손가락을 올린다. 기기가 접촉을 확인(HAND OK)하면 버튼을 눌러 세션 시작 |
| 기준 측정 (약 15초) | 참가자는 편하게 움직이지 않는다 |
| 질문 준비 (READY) | 수집기 화면에 질문과 "N초 기다렸다가"가 나온다 (3~10초 무작위). 기다린다 |
| 질문 (QUESTION) | "지금 질문하세요!"가 나오면 **버튼을 누르고 질문을 읽는다** |
| 답변 (RESPONSE, 약 20초) | 참가자가 답하는 **순간 버튼을 누른다**. 20초 동안 손을 그대로 둔다 |
| 분석·결과 | 결과 단계에서 20~30초 쉰 뒤 **짧게 눌러** 다음 질문 |
| 세션 종료 | "본 질문 5개 완료!"가 나오면 **버튼을 2초 길게 눌러** 세션 종료 |

- 첫 질문은 **연습 질문**(분석 제외)이고, 그 뒤 본 질문 5개가 나온다.
- 손이 떨어지는 등으로 시도가 무효가 되면 수집기가 "질문 N 무효 → 다음 질문은 새로운 대체 질문"이라고 알리고 같은 조건의 다른 질문을 넣는다. 그대로 진행한다.
- 기기의 LED/OLED 표시는 판정 근거가 확인되지 않았다 **[확인 필요: 펌웨어]**. 참가자에게 결과로 설명하지 않는다.

### 4.4 질문 읽는 법

- 수집기 화면의 질문 문장을 **그대로, 같은 속도와 말투로** 읽는다. 말을 덧붙이거나 강조하지 않는다.
- 질문은 모두 예/아니오로 답하는 문장이다 (`question_bank.csv`). 답을 말로 하는지, 몸짓으로 하는지는 코드에 정해져 있지 않다 **[확인 필요: 답변 방식 통일]**. 한 번 정하면 모든 참가자에게 같게 한다.
- 진행자는 참가자가 어떤 질문에 거짓으로 답하는지 모르는 상태를 유지한다.

### 4.5 세션 후 확인 단계 (라벨 확정)

세션을 끝내면 수집기가 **완료된 본 질문을 하나씩** 다시 보여 준다.

```
  질문 3: "운전면허가 있습니까?"
     계획: 거짓  →  실제로는?  [Enter / t / l / x]
```

참가자에게 "이 질문에 실제로 어떻게 답하셨나요?"를 묻고 입력한다.

| 입력 | 뜻 | 저장되는 값 |
|---|---|---|
| Enter | 계획대로 답함 | `condition` = 계획, `confirmed` = `as_planned` |
| `t` | 실제로는 사실대로 답함 | `condition` = truth, 계획과 다르면 `confirmed` = `corrected` |
| `l` | 실제로는 거짓으로 답함 | `condition` = lie, 계획과 다르면 `confirmed` = `corrected` |
| `x` | 헷갈림 | `condition` = test (분석 제외) |

- **`planned_condition`은 계획(수집기가 정한 라벨), `condition`은 확인 후 최종 라벨, `confirmed`는 확인 여부다.** 학습·평가 도구는 `confirmed`가 `as_planned` 또는 `corrected`이고 `condition`이 truth/lie인 본 질문만 쓴다. 확인 단계를 건너뛰면(예: 확인 전에 `quit`) 그 질문은 "미확정"으로 빠진다.
- 확인이 끝나면 "확인 완료: 진실 n개, 거짓 n개, 제외 n개 저장됨."이 나온다.
- 나중에 고칠 때: `fix 3 l`처럼 시도 번호와 라벨을 입력한다.

### 4.6 다음 참가자

- 별칭이 자동으로 다음 번호(P01 → P02)가 된다. 새 기록지를 받아 `new P02 …`를 입력하고 4.2부터 반복한다.
- 수집기를 끄지 않고 여러 참가자를 이어서 진행해도 된다 (같은 run 폴더 안에 세션 폴더가 생긴다).
- 저장된 기록의 무결성을 다시 보려면:
  ```
  .venv\Scripts\python.exe collector\record_session.py --check data\real\experiments\run_20261104_140000
  ```

## 5. 수집량과 현황 확인

### 5.1 제안 수집량

- 참가자 **8~10명 이상**, 확정된 본 질문(진실/거짓) **100~200개 이상**.
- 참가자 1명은 세션 1번에 본 질문 5개가 나온다. 100개를 모으려면 대략 20세션이 필요하다 (무효·제외 제외 전).
- 학습·평가 도구는 참가자가 5명 미만이면 결과를 "탐색용"으로만 취급하고 모델·설정 파일을 채택하지 않는다.

### 5.2 현황 확인 (리포트)

수집기를 끝낸 뒤(같은 포트를 쓰지 않으므로 수집 중에도 되지만, 기록이 확정된 뒤가 정확하다) 저장소 루트에서:

```
.venv\Scripts\python.exe -m training.report
```

- `training\out\report.md`가 만들어진다. 메모장이나 VS Code로 연다.
- "1. 데이터 요약"에 run·시도·참가자 수, 진실/거짓 개수, **제외 사유별 개수**(연습 질문, 미확정, 품질 보류 등)가 나온다. 미확정이 많으면 확인 단계를 빠뜨린 것이다.
- "2. 참가자별 시도 수"로 참가자별 진실/거짓 균형을 본다.
- 확정 데이터가 0건이면 "데이터 없음" 리포트가 나오고 정상 종료한다.
- 리포트는 `data/real`을 읽기만 하고 모델 파일을 만들지 않는다.

## 6. 동의서 양식 (간단본)

> **TruthPulse 생체신호 측정 참여 동의서**
>
> 1. **목적**: 생체신호(심박·맥파, 피부 전기 반응, 손가락 압력)를 이용한 거짓말 탐지 **게임**을 만들고, 판정 방법을 연구하기 위한 측정입니다. **오락·연구용이며 의료 목적이나 실제 거짓 판단(법적·채용 등)에 쓰지 않습니다.** 측정 결과는 진단이 아닙니다.
> 2. **진행**: 손가락을 센서에 올리고, 질문 몇 개에 미리 정한 대로(일부는 거짓으로) 답합니다. 세션 후 실제로 어떻게 답했는지 확인합니다.
> 3. **수집 항목**: 센서 신호(PPG/IR·Red, GSR, FSR)와 측정 시각, 질문 번호, 계획한 답과 실제 답(진실/거짓), 기기 이벤트. **이름, 연락처는 측정 데이터에 저장하지 않으며 별칭(예: P03)만 사용합니다.** 영상·음성은 녹화하지 않습니다 **[확인 필요]**.

## 7. 문제 해결

| 증상 | 해결 |
|---|---|
| `포트 COM6 열기 실패` | 서버, 시리얼 모니터, 다른 수집기 창을 닫는다. `server.cli ports`로 포트 번호 확인 |
| `수동 모드로 실행합니다` | `--bank collector\question_bank.csv`를 빠뜨렸다. `quit` 후 2절 명령으로 다시 실행 |
| `질문 계획이 없습니다` | 첫 질문 전에 `new …`를 입력하지 않았다. 아직 질문이 시작되지 않았으면 지금 `new …`를 입력하면 현재 세션에 붙는다. 질문이 이미 시작됐으면 계획은 **다음 세션**에 붙으므로(코드 기준), 버튼을 길게 눌러 세션을 끝내고 새 세션을 시작한다 |
| `거짓 표시는 최소 3개 필요합니다` | 기록지 표시가 3개 미만. 참가자에게 더 표시하게 한다 |
| `[ESP32] 부팅됨` (세션 도중) | 기기가 재시작됐다. 진행 중 세션은 끝난 것으로 처리된다. 새 세션으로 다시 시작 |
| 리포트에 "미확정"이 많음 | 세션 후 확인 단계를 마치지 않았다. `fix 시도번호 t/l`로 보완 |
