# TruthPulse web

PPT의 앱 기능을 웹으로 옮긴 첫 프로토타입입니다. 프레임워크나 패키지 설치 없이 실행하는 HTML/CSS/JavaScript 앱입니다. PPT 원본은 변경하지 않았습니다.

## 실행

Node.js가 설치된 환경에서 이 디렉터리에서 실행합니다.

```sh
npm run dev
```

브라우저: http://127.0.0.1:4173

```sh
npm test
```

`dist/`가 정적 사이트의 배포 루트이자 소스입니다. 별도 빌드가 없습니다.

## 구현된 기능

- 개인 기준 측정, 질문별 측정, 취소, 새 세션
- PPG/GSR/FSR 가상 신호, 최근 20초 그래프, 변화 요약
- 작은 변화 / 큰 변화 / 접촉 불량 시뮬레이션
- 정답 라벨 기록(0/1/미표기), 기록 검색, 상세 보기
- 최대 100건 브라우저 저장 및 CSV 요약 / JSON 원본 내보내기
- 참가자 별칭과 데모 측정 시간 설정
- 알고리즘 설계 안내, 모바일 레이아웃

가상 데이터는 `source: synthetic_demo`를 사용합니다. 정답 라벨은 결과 계산에 사용하지 않습니다. 확률, 모델 정확도, 실제 진실/거짓 판정을 생성하지 않습니다. 로컬 저장이 차단되거나 가득 찬 경우 안내하고 메모리에서 계속 사용할 수 있습니다.

## 아직 연결되지 않은 부분

실제 센서, ESP32 통신, Python 분석 서버, 학습된 모델, 저주파 피드백 제어는 구현하지 않았습니다. 현재 코드는 이 부분을 가상 신호로 대체한 웹 프로토타입입니다. 현재 데모 전처리/요약을 최종 과학적 판정 알고리즘으로 사용하면 안 됩니다.

## 소스 구조

- `dist/index.html`: 화면 구조 및 알고리즘 설계 안내
- `dist/styles.css`: 반응형 레이아웃
- `dist/app.mjs`: 세션 상태, 화면, 그래프, 저장과 내보내기
- `dist/core.mjs`: 데이터 품질 확인, 데모 생성, 변화 요약, CSV 직렬화
- `tests/core.test.mjs`: 결측/접촉 불량, 정답 독립성, 저장 데이터 및 CSV 처리 검사
- `INTEGRATION.md`: 실제 센서/서버를 붙일 때 사용할 데이터 계약 제안

## 알고리즘 결정 절차

1. 정답을 확인할 수 있는 숫자 카드 등의 과제로 진실/거짓 응답을 수집합니다. 응답 수를 비슷하게 맞추고 순서를 무작위화합니다. 질문마다 정답, 참가자, 세션, 시작/답변/종료 이벤트를 기록합니다.
2. 참가자별 안정 기준과 원본 신호를 함께 저장합니다. 파일럿 시작안은 기준 30초, 질문 관찰 10~15초, 회복 15~30초입니다. 센서와 반응 시간을 확인한 후 조정해야 하는 제안값입니다. 10~20명 × 20~30회도 초기 절차 점검용 규모 제안이며, 충분한 성능 검증을 보장하지 않습니다.
3. 접촉 불량, 결측, 포화, 움직임 구간을 표시합니다. FSR은 거짓 판정용 정보보다 접촉/움직임 품질 관리에 더 유용할 수도 있으므로 비교합니다. 학습용 데이터 수집 중 촉각 피드백은 끄고, 신호를 교란하는 조건을 기록합니다.
4. 처음에는 심박 평균 변화, 맥파 진폭 변화, GSR 최대 변화/반응 면적, FSR 평균 변화/변동 정도처럼 약 6개 특징을 검토합니다. GSR/FSR은 회로 보정 전에는 물리 단위를 가정하지 않습니다. 짧은 답변 구간에서 안정적인 HRV 추정을 가정하지 않습니다.
5. 다수 클래스 기준 모델, 단순 변화량 규칙, L2 로지스틱 회귀를 비교합니다. 채택 전 참가자 분리 검증을 수행합니다. 데이터가 작거나 한쪽 클래스가 빠진 분할은 평가 조건부터 다시 확인합니다.
6. 개인 기준은 해당 세션의 답변 전 데이터로 계산합니다. 그 뒤의 특징 선택, 학습 데이터 전체의 스케일링, 하이퍼파라미터 조정은 학습 폴드 안에서만 수행합니다. 전체 데이터를 먼저 스케일링한 뒤 나누면 안 됩니다.
7. 참가자별 분리 검증으로 균형 정확도, 혼동행렬, 거짓 검출률, 진실의 거짓 오판율을 비교합니다. 새 사람의 반응을 예측하는 목적이라면 같은 사람의 다른 세션도 학습/평가 양쪽에 섞지 않습니다. 기존 사용자 개인화를 평가할 때는 별도 세션/날짜 분할이 필요합니다.
8. 판정 임계값과 필요시 보류 구간은 검증 데이터에서 선택합니다. 최종 평가 세트는 선택 과정에서 제외합니다. 검증 성능이 기준 모델과 구분되지 않거나 참가자별 편차가 크면 모델 채택을 보류하고 추가 측정합니다. 확률을 표시하려면 확률 보정과 보정 오차도 평가해야 합니다.
9. 필터, 특징 순서, 정규화 값, 모델 계수, 절편, 임계값을 버전으로 묶습니다. ESP32로 이식한 후 동일한 원본 신호로 Python/ESP32의 특징 및 점수를 비교합니다. 실험과 실시간 장치에서 같은 인과적 필터를 사용합니다.
